# 拾藏 / Trove — 需求文档

> 状态：最终需求文档  
> 日期：2026-11-08  
> 范围：产品需求；不含技术选型与实现计划。

## 0. 一句话结论

Trove 是**个人长内容库**：把 Bilibili、YouTube、播客变成可听、可读、可检索的内容，把电子书变成可读、可检索的文本；**音频播放是核心消费方式**，文本是自动整理和检索的载体。MVP 用 **Mac 处理主机 + Host Console Core + Consumer Web Shell（[Q10](#q10) gated）**，手机/桌面浏览器连接后即可收藏、提交处理、播放、阅读、搜索。**当前阶段的绑定目标是个人自用验证**；大众市场 + 云端处理是后续假设，不进 MVP 验收。Android 是长期主入口；电子书在 MVP 只读，不做 TTS。视频播放、时间戳跳转、同步滚动、标注、语义检索、Topic 层、PDF 都不是当前阶段的核心。

## 1. 产品定位

### 1.1 一句话

> 把 Bilibili、YouTube、播客变成可听、可读、可检索的内容，把电子书变成可读、可检索的文本；音频播放是核心消费方式，文本是自动整理和检索的载体；MVP 用 Mac 主机 + Host Console Core + Consumer Web Shell（Q10 gated）；Android 是长期主入口。

### 1.2 是什么

- **音频优先**：播放是核心消费方式；播放器要好用，但不是差异化。
- **文本为骨**：音视频转成文本，用于阅读、检索、自动整理。
- **统一库**：视频、播客、电子书进入同一个库，用同一套 Tag/搜索组织。
- **自动整理**：入库时自动生成摘要、Tag，不要求用户手动经营。
- **本地拥有**：原始来源信息、音频、文本、索引在用户自己的主机上，可迁移、可重建。
- **Host Console Core（MVP，长期）**：Mac 主机提供的 Web 管理/入库/状态/搜索界面；手机/桌面都能用；导出 P1；不做桌面 App。
- **Consumer Web Shell（MVP 验证壳）**：浏览器里的播放/transcript/Continue/搜索定位；Q10 gated，预期被 Android 客户端替代。
- **Android 优先（长期）**：Android 是最终主入口；Mac 是验证与处理宿主。
- **个人验证优先**：先证明“会听、会搜、会回来”，再谈大众市场。
- **大众市场（后续假设）**：最终消费者形态可能是 Android + 云端处理；MVP 不按云端/合规/单位经济设计。

### 1.3 不是什么

- 不是纯播放器：播放是核心体验，但差异化在文本化、自动整理、检索。
- 不是视频播放器、流媒体客户端或内容平台。
- 不是每日 feed、学习计划、主题冲刺或打卡工具。
- 不是社交、推荐或多用户产品。
- 不是笔记软件、任务管理器或知识图谱工具。
- 不是视频剪辑、内容生产或发布工具。
- 不是必须安装的桌面软件：MVP 以 Host Console Core + Consumer Web Shell 为主，桌面 App 不是前提。
- 不是桌面端产品：桌面 App 不是主形态；最多作为主机的启动器/管理工具。
- 不是电子书音频产品：MVP 电子书只读，TTS 后置。
- 不是云 SaaS：云端处理是后续假设，不是 MVP 默认。

## 2. 目标用户与场景

### 2.1 用户

- 单用户：内容收藏者本人。
- 中文优先，英文内容可读、可听、可搜。
- 收集长视频、播客、电子书，主要靠“听”，其次靠“读”。
- 愿意手动单条收藏，不需要批量导入或自动订阅。

### 2.2 核心任务（JTBD）

1. **收藏**：看到好内容，粘贴链接/拖入文件/选播客单集，系统自动处理。
2. **转文本**：把音视频变成可读文本，把电子书变成可检索文本。
3. **听**：像播客/有声书一样播放音视频内容，这是主要消费方式。
4. **读**：需要时打开 transcript 看文字；电子书直接读。
5. **找回**：搜一个关键词，知道哪些内容提到它，并打开对应段落。
6. **浏览**：按 Tag、类型、状态、来源看自己的库。
7. **整理**：自动摘要/Tag；偶尔手动修正 Tag 和标题。
8. **可选**：对某段文本写一句自己的想法（P2）。

### 2.3 使用场景

- **验证期**：Mac 作为处理主机，浏览器打开 Host Console Core / Consumer Web Shell；重点验证“听 + 搜”是否顺手。
- **最终形态**：Android native + 云端处理（后续）；MVP 不做。
- **内容量**：先用 20 条真实内容验证管线/标签；搜索评估单独准备 50+ 条；长期按 1,000 条设计。
- **语言**：中文为主，英文为辅。
- **网络**：MVP 浏览器客户端不承诺离线；主机不在时不能播放/阅读。离线播放/阅读/搜索是 V1 Android 的需求。

## 3. 核心概念

术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准；下表只列与本需求直接相关的概念。

| 概念 | 定义 | 备注 |
|---|---|---|
| Item（条目） | 一个可消费的内容单位：一个视频、一集播客、一本书 | MVP 一个入库 URL 最多产生一个 Item；播放列表/多 P 拒绝 |
| Source（来源） | 原始 URL/平台/本地文件路径 | 必须保留原始 URL/路径 |
| Library（库） | 用户全部 Item 的集合 | 在 MVP 中位于 Mac 主机 |
| Content Package（内容包） | Item 在库中的文件集合：来源元数据、音频、transcript、书文件、AI 结果 | 导出单位 |
| Audio（音频） | 从音视频抽取的本地音频 | 主要消费产物；视频不落盘 |
| Text（文本） | 音视频转写文本或电子书文本 | 阅读和检索的主对象 |
| Tag（标签） | 自由细分类 | 自动生成，可修正；MVP 唯一分类层 |
| Topic（主题） | 受控粗分类 | 不做；50+ 条后再评估 |
| Annotation（标注） | 用户对某段文本的笔记 | 可选，P2 |
| Processing Run（处理运行） | 把 Source 变成可消费产物的一次尝试 | 失败可重试/续跑 |
| Processing State（处理状态） | 排队/下载/抽音频/转写/整理/索引/完成/失败 | 属于 Processing Run |
| Consumption State（消费状态） | 未开始/进行中/完成 | 属于用户/Item；与处理状态独立 |
| Host Console（主机控制台） | 处理主机提供的 Web UI/API：入库/处理/管理/搜索/导出；不是主要消费端 | MVP 是 Mac；长期保留 |
| Consumer Web Shell（消费验证壳） | 浏览器里的播放/transcript/Continue/搜索定位 | MVP 验证用；Q10 gated；预期被 Android 替代 |
| Export（导出） | Library 或 Item 子集的 zip 内容包 | 可迁移/本地拥有的证据 |

## 4. 核心流程

```
Host Console Core / Consumer Web Shell（浏览器）
        │  HTTP(S)
        ▼
  Mac 主机 Web API + 处理
        │
        ├─ 下载 / 抽音频 / 转写 / 调 DeepSeek
        ├─ 内容库 / 索引 / 导出
        └─ 播放 / 阅读 / 搜索
```

- **Host Console Core**：入库、状态、管理、搜索；导出 P1；不依赖 Q10。
- **Consumer Web Shell**：播放、transcript、Continue、搜索定位；Q10 gated，验证壳。

产品核心循环：

```
发现 → 收藏 → 转文本 + 自动整理 → 听（核心）→ 读 transcript/电子书（次要）→ 检索/回顾
                                                         │
                                                         └─ 可选：标注（P2）、导出（P1）
```

- **收藏**：粘贴 URL、上传本地音视频/EPUB、粘贴播客 feed 选单集。
- **转文本**：主机下载/抽音频/转写；电子书提取章节和文本。
- **自动整理**：摘要、Tag（不做 Topic）。
- **听**：在控制台/客户端播放音频，这是主要消费方式。
- **读**：需要时打开 transcript；电子书用阅读器读。
- **检索/回顾**：关键词搜索、Tag/类型/状态/来源过滤。
- **标注**：P2，不属于主循环。

## 7. 数据要求

- 每个 Item 必须保留：`source_url_raw`、`source_url_canonical`、`platform`、`source_type`、标题、作者、发布日期、抓取时间。
- 视频来源：保留原始视频 URL；只存音频和文本，不存视频文件。
- 本地文件来源：保留原始文件路径；EPUB 和本地音频复制进库；本地视频只存路径 + 抽出音频；不删除用户原文件。
- 转写文本：分段保存，带 start/end 时间戳；不要求词级时间戳。
- 电子书：保留原文件、章节结构、正文；MVP 不做 PDF。
- AI 结果：摘要、Tags、模型名、prompt 版本、生成时间；Topic/entities 不在 MVP。
- 处理记录：Processing Run 的阶段、状态、失败原因、重试/续跑信息。
- 消费记录：播放位置、阅读位置、Consumption State（未开始/进行中/完成）。
- 同步清单（V1）：Item 级 `version`/`updated_at`/`deleted_at`；文件级 `kind`/`sha256`/`size`/`mime`；用于 manifest + cursor + tombstone。
- 同步状态（V1）：播放位置、阅读位置、Consumption State、Tag 版本、`device_id`、`updated_at`；单用户按字段 last-write-wins。
- 检索索引：覆盖标题、摘要、转写文本、书文本、Tags；结果按 Item 聚合。
- 导出：zip 包含来源元数据、音频、transcript、书文件、AI 结果、Markdown 索引；本地视频只含 `source.json` + 音频。
- 标注（以后）：文本 quote + position；时间戳可选，不作为主锚点。

## 8. 范围与优先级

### 8.1 MVP（Mac 主机 + Host Console Core / Consumer Web Shell）

**唯一范围来源**：MVP = 以下全部 P0 + 明确列出的 P1 短名单；不在本节的 P1/P2/P3 都不属于 MVP。

**P0（必须）**

- **Host Console Core（长期）**：入库（URL/本地/EPUB/播客 feed）、队列/状态/失败/重试、Library、元数据编辑、搜索、来源 URL、删除、认证、API；Tag 编辑随 P1，导出为 P1；基础播放/transcript 预览用于 QA。
- **处理**：抽音频、分段转写、EPUB 章节/文本、摘要、Tag、索引；去重、队列持久化、取消排队。
- **消费（听验收设备按 Q10 门控）**：音频播放器、播放进度、EPUB 薄阅读器/系统阅读器、消费状态。
- **检索**：关键词搜索、按 Item 聚合、匹配段落、来源/类型/作者/日期、中文两字词。
- **浏览**：Library 列表、Library + Search + Add 导航（Continue 入口随 P1）、Inbox 过滤/徽标。
- **管理**：来源 URL、编辑标题/作者、删除 Item、Tag 归一化。
- **安全**：单用户认证、局域网、URL 校验、上传限制、不暴露开放下载器。

**P1 短名单（MVP 应该，且只包含这些）**

- transcript 阅读（FR-37）。
- 阅读进度（FR-39）。
- Continue（FR-36）。
- 基础过滤：类型/消费状态/Tag/来源（FR-50）。
- Item 上 Tag 编辑（FR-28）。
- 搜索结果打开到匹配段落（FR-52）。
- 导出 zip（FR-64）。
- 取消运行中任务 best-effort（FR-11）。
- PWA 安装（FR-86，可选，依赖 HTTPS，不进验收）。
- **Consumer Web Shell（FR-87）**：交付浏览器播放/transcript/Continue/搜索定位；Q10 通过才作为手机听验收，失败则收缩到桌面，native 进下一里程碑。

**MVP 边界**

- Host Console Core 不依赖 Q10；Consumer Web Shell 依赖 Q10，是验证壳，不是最终消费端。
- 不做桌面 App；不做 Web 离线；不做 Android native；不做 Topic/PDF/TTS/标注/语义搜索/Up Next/睡眠定时/全局 Tag 合并。
<a id="q10"></a>
- **Q10（手机浏览器“听”的可行性）**：手机浏览器能否承担主要听设备？验证：先跑 1 周手机播放 spike（连续播放、后台/锁屏、倍速、进度续听、媒体通知）；通过 → 手机浏览器是“听”的验收设备；失败 → 桌面浏览器验收，native 播放器进入下一里程碑。

### 8.2 V1（Android 客户端）

- Android 是主入口：播放、阅读、搜索、浏览、收藏。
- 客户端形态：native vs PWA 由后续技术选型决定；PWA 只用于验证/管理，不作为核心播放器的默认答案。
- 内容来源：验证期接 Mac 主机；大众市场版接云端处理服务；两者共用同一 API。
- 离线播放/阅读/搜索；本地缓存已同步内容。
- 同步采用 app-managed sync（见下）。
- 音频播放是核心：后台播放、媒体通知、倍速、进度。
- 阅读 transcript 是次要入口；电子书阅读可用。
- 标注 P2。

**同步（V1，app-managed sync）**

- 文件单向、不可变：每个 Item 文件带 `sha256`/`size`/`mime`/`version`；手机只下载，不改服务端文件。
- Manifest + cursor：按 `updated_since` 返回变更 Item 和文件清单；删除用 tombstone。
- 可续传下载：HTTP `Range` + `ETag`；后台下载；Wi-Fi/充电约束；校验 sha256；存储配额。
- 本地数据库/索引：Item 元数据、文件路径、下载状态、播放/阅读位置、Tag 版本。
- 状态双向：progress/tags 通过 API 写回；单用户按字段 last-write-wins，带 `device_id` 和幂等键。
- 选择性同步：按 Item/Tag/大小；不整库同步。
- 音频用本地播放器（native 优先）；EPUB 用 native 阅读器；离线搜索用本地索引。
- 第三方文件同步（Syncthing/WebDAV）只作为自托管/验证桥，不是产品路径。
- 验收：断点续传、校验通过、删除同步、进度/Tag 冲突可解释、选择性同步不下载整库。

### 8.3 以后

- Topic 层（50+ 条后评估）、PDF、TTS、实体抽取、标注、语义搜索、完整 EPUB 渲染（图片版式/脚注/书内搜索）、Up Next、睡眠定时、全局 Tag 合并、独立 Markdown 导出、备份/恢复 UI、视频播放、云同步。
- 大众市场/云端处理/合规/单位经济。
- Android native 的具体形态与技术选型。

### 8.4 不做

- 每日 feed/streak、主题冲刺、社交、推荐、多用户、任务管理器、视频剪辑、云 SaaS、iOS。
- 视频播放、时间戳跳转、同步滚动、语义问答、开放下载代理、DRM 绕过。
- 桌面端 App 作为主形态。

## 9. 验收标准

### 9.1 管线与质量

- 来源分列：B 站 8/10、YouTube 8/10、播客 RSS 8/10、EPUB 10/10、本地文件 10/10；失败按原因分类（地区/登录/DRM/网络/解析）。
- 20 条真实内容入库；1 小时视频端到端 <30 分钟（M1 Pro）。
- Tag 可用率 ≥70%；摘要能概括内容、事实错误少。
- 中文两字关键词可命中；英文短内容可转写并命中关键词。
- 同 URL/文件重复添加不重复下载；失败可重试并续跑；取消排队有效；运行中取消 best-effort。

### 9.2 搜索评估

- 单独准备 50+ 条真实内容（可与 20 条管线集重叠，但不能只挑好搜的）。
- 30 个预注册 query：10 个已知条目、10 个探索式、10 个两字中文词。
- 按 Item 判分；相关 = 该 Item 有段落提到/回答 query，段落作为证据；记录漏召回。
- 指标：recall@10、首个相关结果排名、按内容类型分列；由用户判分，LLM 只做辅助。

### 9.3 消费

- **Host Console Core**：桌面/手机浏览器能完成入库、查看状态、搜索、元数据编辑、来源 URL、删除；Tag 编辑随 P1，导出为 P1；这部分不依赖 Q10。
- **Consumer Web Shell（Q10 gated）**：音频条目可连续播放，支持进度/倍速/后台播放；transcript 可读；电子书可用薄阅读器翻章/读正文，或调用系统阅读器；来源 URL 可见。
- 手机浏览器（Q10 通过）能完成：收藏链接、查看状态、播放、读 transcript、搜索、看来源 URL；Q10 失败时消费操作收缩到桌面浏览器。
- 完整 EPUB 渲染（图片版式/脚注/书内搜索）是 V1/native 的验收，不是 Web MVP 的承诺。
- MVP 不承诺离线；主机不在时不能播放/阅读。

### 9.4 行为与产品价值

- 4 周行为门槛：≥50% 入库内容至少开始消费一次；≥30% 完成；≥3 次/周搜索且 ≥70% 搜索成功；4 周后仍愿意继续用。
- 不达标就缩减范围、调整定位或停，不继续堆功能。
- 搜索成功用每周手动记录（query、是否找到、漏了哪条）；消费状态用应用内进度自动计算。

### 9.5 数据与安全

- 删除 Item 只删派生文件/索引/库记录，不删用户原文件；导出 zip 可迁移。
- 未认证不能操作；默认只绑定局域网；公网访问必须 HTTPS/VPN；不开放任意 URL 代理；URL 校验禁止内网/元数据地址；上传类型/大小限制。
- 主机休眠/重启后队列持久化，恢复后继续；不丢任务、不重复处理。
- 100 小时音频 + 100 本书 <5GB（视频不落盘）；复制 EPUB 后按真实书库重算。

## 10. 技术选型与后续范围

- 主机形态（Mac/NAS/云端）、Android native vs PWA、同步的具体实现、云端/大众市场/合规/单位经济，不在本文档范围；由后续技术选型/ADR 决定。
- 本文档只固定产品行为、数据边界和验收标准；技术选型不得改变本文档的产品约束（个人验证优先、MVP 不做云端/离线 Web、V1 Android 离线等）。

## 11. 总结

Trove 的需求可以收敛为一句话：

> **把长内容变成可听、可读、可检索的本地内容，自动整理，按关键词和 Tag 找回来。**

因此当前阶段的重点是：**收藏 → 转文本 → 自动整理 → 听 → 读/检索**。  
不是：视频播放、时间戳跳转、同步滚动、标注工作流、语义问答、社交推荐、Topic 分类、PDF、TTS。  
MVP 用 Mac 主机 + Host Console Core + Consumer Web Shell（Q10 gated）验证“听 + 搜”；Host Console Core 长期保留，Consumer Web Shell 是验证壳；Android 是长期主入口，但客户端形态和技术选型后续再做。大众市场的云端/合规/单位经济是后续假设，不进入 MVP 验收。音频播放是核心；Q10 门控先证明它在目标设备上成立。已同步内容的离线播放/阅读/搜索是 V1 Android 的需求，不是 MVP Web 的承诺。
